# Panel-to-Coolify: скилл для миграции сервера

**Русский** | [English](README_EN.md)

Скилл помогает ИИ-ассистенту переносить работающие серверы с FastPanel, cPanel/WHM, Plesk и ISPmanager на Coolify. Он собирает карту зависимостей, помогает подготовить проверку маршрутов и восстановление, а затем аккуратно убрать панель. Подходит для совместимых с Agent Skills агентов, включая Codex и Claude Code.

Миграции различаются: универсальный скрипт не может доказать безопасность удаления пакетов или обеспечить откат при обрыве SSH. В этом репозитории команды переключения и удаления **составляют план и отказываются вносить изменения**. Само переключение выполняется отдельно подготовленными и проверенными для конкретного сервера действиями.

## Установка

```bash
npx skills add MikeMorette/panel-to-coolify-skill
```

Или клонируйте репозиторий в каталог скиллов вашего агента:

```bash
git clone https://github.com/MikeMorette/panel-to-coolify-skill.git ~/.agents/skills/panel-to-coolify
```

Например, попросите ассистента:

> Используй `panel-to-coolify`, чтобы перевести сервер на Coolify. Сначала проверь действующие сайты и зависимости, учти допустимый простой и согласованный объём резервных копий, затем подготовь переключение и удаление панели.

## Как проходит работа

Скилл ориентирован на быстрый переход: минимально необходимые проверки объединяются в один-два SSH-вызова на этап. Повторные аудиты, тяжёлые стенды и дополнительные субагенты не запускаются без конкретной причины или просьбы пользователя; после выполнения условий ассистент переходит к уже разрешённому действию.

1. Ассистент одним или несколькими пакетными SSH-запросами собирает актуальные маршруты, сертификаты, приложения, базы и службы; уточняет неизвестные зависимости и фиксирует исходное состояние.
2. Согласует объём копирования и план восстановления. Можно отказаться от полного бэкапа или сохранить только выбранные данные; ограничения восстановления должны быть озвучены. Снимок конфигурации не заменяет копию базы.
3. Проверяет действующие приложения, DNS, HTTPS и продление сертификатов. Ненужные проекты не запускаются; допустимый короткий простой и отказ от тяжёлого стенда учитываются.
4. Готовит проверенные именно на этом сервере действия переключения и независимый механизм отката. После перехода сравнивает реальные ответы с исходными.
5. Перед удалением панели проверяет её зависимости, конфигурации, пакетные сценарии и точный состав операции. Сохраняет требуемые Apache/PHP, почту, FTP, SSH, данные и файлы сайтов.

Не гарантируются нулевой простой, работоспособность всех возможных панелей и проверка бизнес-функций одним HTTP-ответом. Неизвестные зависимости требуют отдельной проверки.

## Скрипты

| Команда | Назначение |
|---|---|
| `scripts/preflight-inventory.sh [--public-ip IP] [--dns-limit N] [--git-scan]` | Предварительная инвентаризация; ограничивает DNS-проверки, не запускает `pm2 list`/`forever list` и обходит файловые деревья только с `--git-scan`. |
| `scripts/backup-state.sh` | Необязательный снимок конфигураций и сертификатов, содержащий секреты; запускать только если такой объём копирования согласован. Это не полный бэкап и не дамп БД. |
| `scripts/stage-verify.sh --domains example.com --target 127.0.0.1:443` | Проверка маршрута и TLS; по умолчанию проверяет имя и цепочку сертификата, не следует за редиректами. |
| `scripts/cutover-and-rollback.sh --dry-run ...` | Печать плана. `--apply` и `--rollback` заблокированы: универсального независимого watchdog здесь нет. |
| `scripts/purge-panel-safe.sh --panel fastpanel2` | Только инвентаризация и симуляция удаления пакетов. `--apply` заблокирован. |
| `scripts/start-guard.js` | Предварительная проверка занятости порта; она сама по себе не исключает одновременный запуск процессов. |

`stage-verify.sh --write-receipt` создаёт запись только о выполненных маршрутных проверках с проверенным HTTPS. Она не доказывает работу авторизации, записи файлов или автоматического отката и не является разрешением удалить панель.

Временные ошибки маршрута повторяются ограниченно; первая ошибка остаётся в выводе. Подтверждение реального сценария самим пользователем учитывается с указанием источника, без повторного запроса токена для той же проверки.

Дополнительные правила и нюансы: [безопасность](references/safety-invariants.md), [особенности панелей](references/panels-matrix.md), [маршруты и сертификаты Coolify](references/coolify-templates.md).

## Проверки разработки

```bash
bash tests/run.sh
```

Тесты работают на локальных фикстурах и не подключаются к продакшен-серверу. Реальное переключение и восстановление требуют проверки отдельно.
